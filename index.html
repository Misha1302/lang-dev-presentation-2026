The counterargument

Sometimes the planner is the bigger problem

Bad outcome

You replace understandable compiler code with distributed declarations and a global planner, but hidden semantic assumptions still decide correctness.

explicit pipeline → known sequence

MLIR-style legalization → local IR legality
whole-language planner → cross-owner hard constraints

Appendix · implementation boundary

Current UT facts vs proposed architecture

Current implementation

LanguageCompiler builds LanguagePlan; route phase chooses minimum declared Cost conversion skeleton, then inserts selected same-contract passes; runtime materializes exact plan.

Proposed model

Make hard obligations and artifact properties first-class enough for feasibility before preference. Route becomes materialized output, not the semantic input model.

Appendix · same-contract trap

Mandatory vs optional is orthogonal to artifact identity

Bad shortcut

same contract ⇒ mandatory pass
different contract ⇒ optional route edge

Better rule

mandatory comes from semantics, backend legality or policy; optional optimization remains preference.

Appendix · selection

Selection is not execution obligation

Selected

available in the contribution graph; may satisfy dependencies or provider choices.

Executed

appears in the final concrete route or plan because an obligation or admissible implementation requires it.

Appendix · artifact properties

Representation contract is not semantic state

Two values can both be AIR<wist.air/v1> while only one is typed, lowered, verified, or target legal.

Model only composition-relevant properties. Do not build a theorem prover on stage.

Appendix · local evidence

Richer facts already exist locally

UT's IR-stage design already uses the stronger idea locally: stages can require, produce, preserve and invalidate facts. The whole-language route layer is weaker than that local model.

Appendix · hostile Q&A

The strongest objection

“You replaced an explicit compiler pipeline with distributed declarations and a global planner, but if semantic assumptions remain hidden, the system is simply more complex without becoming more correct.”

Answer: use the planner only where relevant cross-owner correctness constraints can be expressed and checked better than local mechanisms. Otherwise, do not use it.
