What if Delegates were an independently authored language feature — not a built-in assumption of one compiler?

The difficult part is not parsing delegate. The difficult part is making the same feature remain meaningful across semantic systems it did not know when it was authored.

01 · A language feature crosses boundaries

A compiler plugin usually extends a compiler whose language is already known.

A reusable language feature has a stronger contract: it must carry programmer-visible behavior through parsing, semantics, lowering, tooling, optimization, and backend behavior — while depending on as little concrete language policy as possible.

13 · A falsifiable architecture hypothesis

The claim is in the connection, not in inventing every brick.

Modular language composition exists. Capability-style interfaces exist. Proof obligations exist. Analysis invalidation exists. The potential contribution is a disciplined ownership boundary connecting independent feature authoring to later safe specialization.

independent feature authoring↓semantic requirements↓language resolution↓scoped program evidence↓consumer-owned obligation↓safe specialization

Use the simpler alternative when it wins.

If ordinary adapters remain simpler and preserve enough precision, use them. If this architecture introduces more ceremony and coupling than it removes, the experiment fails.

What would falsify it?

  • pairwise adapters stay consistently simpler;
  • capability contracts lose semantic precision;
  • evidence cannot remain trustworthy across representations;
  • coordination costs more than the coupling it removes.
Strong alternatives already cover important parts of the problem. The open question is the cross-phase ownership boundary.

Research notes

Appendix / FAQ

Compact answers for discussion after the main narrative.

Why not ordinary adapters?

For small or stable integration matrices, adapters may be the better design. The architecture is only useful if explicit semantic requirements and evidence ownership reduce net coupling without losing precision.

Why not MLIR?

MLIR already provides strong interfaces, effects, legality, conversion, and analysis infrastructure. The research question here is different: whether independently authored language features can exchange scoped semantic evidence through a disciplined ownership model from composition to specialization.

Is this already implemented?

No. UniversalToolchain provides bounded witnesses for pieces such as declarative profiles, staged planning, route feasibility, selected cross-backend behavior, and limited deabstraction. The full interaction among independently authored type semantics, effects, ownership, and evidence lifecycle remains a research target.

What does “proof” mean here?

A transformation-owned set of conditions whose truth is established from scoped semantic evidence. It need not mean an interactive theorem prover; it means the compiler can justify the legality conditions required for that transformation.

What happens when evidence is unknown?

The transformation does not fire. The compiler keeps the safe generic path.

What happens when evidence is contradictory?

Fail closed unless an explicit reconciliation rule can resolve the contradiction under the current scope and assumptions.

Is this zero-cost?

No universal zero-cost claim is made. Generic machinery may be erased only at program points where the required obligations are established.

How does evidence survive lowering?

Only through explicit preservation, transport, or recomputation rules. Otherwise it must be invalidated rather than silently trusted.

What exactly is the potential contribution?

The disciplined connection: independent feature authoring → semantic requirements → language resolution → scoped evidence → consumer-owned obligation → safe specialization.

What would falsify the architecture?

If adapters stay simpler, capability contracts lose precision, evidence cannot remain trustworthy across representations, or coordination overhead exceeds the coupling removed, the architecture should be rejected.
