Planner/runtime boundary

Runtime executes the plan; it does not rebuild the language

Planner

  • select providers
  • resolve conflicts
  • order contributions
  • build artifact routes
  • choose exact executor

Runtime

  • validate plan/provider match
  • materialize components
  • assemble the selected route
  • execute
  • report runtime failures
Runtime validation ≠ second planner

Takeaway

Extensibility is not just making components pluggable

When independent components must form one language, someone has to own global composition decisions.

Appendix · title

Why the accepted title stays

The public talk title promises disappearing abstractions. The main deck now delivers it through a staged argument: global composition decisions become fixed facts; execution/specialization can consume those facts without re-solving composition.
