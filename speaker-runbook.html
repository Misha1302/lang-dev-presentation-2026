Build the Language,
Then Make the Abstractions Disappear

Use this as the three-hour memorization map for the deployed deck. Do not memorize a script. Memorize each slide as: where we are, one anchor sentence, and the transition to the next slide.

Talk contract

25 minutes plus Q&A. The slide metadata now allocates 17:45; rehearse for about 18–20 minutes, leaving buffer for English pacing and live navigation.

Main story

Feature crosses compiler stages → modules own contributions → a dialect selects modules → LanguagePlan resolves composition → Bytecode/AIR/CIL make execution concrete → parity keeps meaning stable.

Research outlook

Slides 9–15 are not a second full talk. Present them as a short outlook: when several modules own semantic premises, the optimizer should ask for an obligation, not know every producer.

Opening memory

One-line thesis: extensibility belongs at composition boundaries; execution should consume resolved, concrete operations.

Opening: “I will follow one small Wist pricing expression through UniversalToolchain: first as an extensible language, then as a concrete executable artifact.”

Slide-by-slide anchors

01

Open to extension. Concrete at execution.

Anchor: This talk is about two moments: open composition and concrete execution.

Transition: But why is language extensibility difficult in the first place?

02

A feature cuts across the whole compiler

Anchor: A language feature is a vertical slice through the compiler, not one plugin hook.

Transition: So ownership must move from the central compiler into feature modules.

03

Make the extension points module-owned

Anchor: The module owns its contributions; the language definition only selects them.

Transition: Once selection is explicit, we can build an actually restricted language.

04

The selected modules are the language

Anchor: These selected modules literally define the surface of this language.

Transition: But local selection is not enough; global choices still need resolution.

05

Composition closes into one LanguagePlan

Anchor: LanguagePlan turns open composition choices into one immutable answer.

Transition: Once we have that answer, we can follow an actual program through it.

06

One Wist program becomes executable operations

Anchor: The same expression becomes progressively more concrete: source, binding, Bytecode, AIR and backend routes.

Transition: And once the backend knows enough, representation machinery can disappear.

07

Known slot + known type can erase a load sequence

Anchor: Known slot plus known type lets us replace three generic operations with one typed operation.

Transition: Different representations are fine only if they still preserve one meaning.

08

One source must not acquire two meanings

Anchor: Backends must execute resolved semantics, not invent their own semantics.

Transition: The binder owns this answer today; future transformations may need premises owned by several components.

09

Structure is resolved; shared meaning is still a question

Anchor: The plan composes structure, but it does not automatically compose every semantic argument.

Transition: Make that concrete with one optimizer question.

10

The vectorizer should not know who owns the answer

Anchor: The vectorizer should ask for a property, not know every producer of that property.

Transition: But someone has to explain why that property is true.

11

A semantic answer can be derived from owned evidence

Anchor: An answer is a derivation from independently owned evidence.

Transition: The extensibility property appears when a premise is missing.

12

A new module can make an old query provable

Anchor: A new producer can make an old query provable without changing the consumer.

Transition: That suggests a small shared contract.

13

Publish evidence. Derive facts. Query obligations.

Anchor: Providers publish facts, rules derive facts, consumers query obligations.

Transition: Shared evidence is useful only if we know when it is still valid.

14

Provenance explains success and safe stop

Anchor: Provenance answers two questions: why is this true, and when does it stop being true?

Transition: These ingredients have serious precedents; the question is the integration boundary.

15

Prior art supplies the pieces

Anchor: This is an integration hypothesis, not a claim to invent inference or modular compilers.

Transition: Whatever mechanism wins, execution should consume decisions rather than repeat open-world negotiation.

16

The abstractions disappear at two different gates

Anchor: There are two disappearance gates: composition choices resolve into the plan; representation specializes into execution.

Transition: End on the three responsibilities the deck connected.

17

Compose the language. Agree on meaning. Execute concrete operations.

Anchor: Modules compose structure, backends agree on meaning, lowering produces executable operations.

Transition: Thank you. Questions?
